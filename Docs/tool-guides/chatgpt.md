# ChatGPT 项目使用指南

与 Google AI Studio 共用 Git 分支 `docs-sync`。Studio 适配见 `docs/tool-guides/google-ai-studio.md`。

Single Developer Mode：仓库 public 读/写；允许创建、修改、新增资产档案。不需要 PR。不得删规范、不得覆盖 LOCKED、不得改已发布视觉母版。概念材质卡 `MAT-*` 只用于出图，不绑定 UE 网格材质。

## 推荐方式

优先通过 GitHub 连接读取指定仓库和 commit。

若使用项目上传文件：

- 上传 `spec-manifest.yaml`；
- 上传相关 Markdown/YAML；
- 只在当前操作模式需要时上传/读取视觉母版；
- 在项目说明中记录来源 commit；
- 上传文件视为快照，不是新的权威分支。

## 每次新对话 / 新任务

先读取并遵守：

1. `spec-manifest.yaml`；
2. `Docs/governance/source-of-truth.md`；
3. 船只系统规范；
4. **`Docs/specs/assets/ships/production-rules.md`**；
5. 目标船 `design.md`；
6. 当前指定/绑定的材质卡；
7. `integration.yaml`；
8. 只有在 `production-rules.md` 判定当前任务允许时，才读取视觉母版；
9. 本工具指南。

最小报告：

- 实际读到的文件；
- 规范 document_version 与 status；
- LOCKED / REVIEW / UNSET；
- 不可访问来源；
- 当前任务属于文字交流、直接改图还是 clean-slate 重新生成；
- 当前是否允许读取既有视觉母版。

不得假称读取了不存在或未访问的独立文件。

## 先文字，后出图

- 不因为最终目标是视觉资产就上来直接生成图片。
- 讨论、评审、诊断、规则修改、材质分析、方案比较、流程调整默认只做文字工作。
- 只有用户明确要求“出图 / 生成 / 绘制 / 重出 / 重新出”等视觉交付时，才在完成规则核对后进入出图。
- “提到图片”不等于“要求生成图片”。

## 出图工作：先判定操作模式

### 直接改图

用户要求在指定图片上修改时：

- 该图是直接编辑基准；
- 不擅自变成从头重画；
- 未要求整体重设计时，只修改用户明确指出的内容；
- 当前结构、材质、颜色硬约束仍有效。

### 重新 / 重出

用户说“重新 / 重出 / 从头做 / 推翻上一版”时：

- 只读取当前权威文字规则、目标资产文字设计档案、当前材质卡和用户本次明确要求；
- **不得读取上一版概念图或视觉母版图片作为生成输入**；
- 不使用历史提示词、旧 brief、被否决图片、助手以前的描述或模型记忆；
- 只有用户明确说“基于母图修改 / 参考上一版 / 在这张图上改”时，才允许读取指定旧图。

已发布视觉母版仍是版本档案；clean-slate 重新生成只是排除其图片输入，不会自动删除其版本记录。

## [概念图]

- `[概念图]` 默认是一张**定调关键图**，不是多视图板。
- 不自动增加侧/前/后/顶视图、材质球、零件拆解或细节特写。
- 多视图只在用户明确要求或进入对应多视图阶段时制作。

## 材质卡

- 材质卡是硬约束，不是灵感参考。
- 指定 `MAT-*` 时必须先读取当前权威版本；读不到不得猜。
- 船只本体不得自行加入材质卡没有的颜色；新增颜色必须先修改/批准材质卡。
- 材质卡未允许的表面效果不得自行添加。
- 参考图能否参与生成，服从材质卡自身的 usage；标记 archive-only 时不得作为生成输入。

## 视觉版本归档

- 不依据聊天中被否决的图片；
- 图片通过后更新视觉修订号、SHA-256 和 ADR；
- 未通过的图片不得进入活跃权威路径。

本指南只做 ChatGPT 适配；船只资产制作事实以 `Docs/specs/assets/ships/production-rules.md` 为权威，不在本文件维护第二套规则。
