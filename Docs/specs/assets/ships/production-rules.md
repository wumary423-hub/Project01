# 船只资产制作全局规则

本文件是 Project01 所有船只资产的现行制作流程。旧的“整船线稿透视图 → 整船线稿多视图 → 整船概念多视图 → 整船最终多视图”流程已经废止，不得继续作为提示词、输入依赖或阶段门禁。

## 1. 先讨论，明确要求后才执行

1. 讨论、评审、诊断、规则修改和方案比较默认只做文字工作。
2. 只有用户明确要求绘图、建模、改文件或进入下一阶段时，才执行对应工作。
3. 每次执行前读取：`spec-manifest.yaml`、本规则、船只系统规范、目标船 `design.md`、材质卡和 `integration.yaml`。
4. 历史聊天、旧提示词、被拒绝图片、废止母版和旧流程产物不得自行成为输入。

## 2. 现行六阶段流程

| 阶段 | 名称 | 主要输出 | 说明 |
|---|---|---|---|
| 1 | 完整效果概念图 | 一张完成度高的整船概念图 | 锁定整船风格、材质语言和部件组合后的整体观感 |
| 2 | 部件拆解 | 部件清单、复用判断、必要的独立部件设计图 | 不是简单裁切概念图；被遮挡面需要单独补画 |
| 3 | 主零件制作与流程验证 | 首先制作船身；每个主零件可有自己的子流程 | `ShipType_SmallSailer01` 当前验证输出为独立 `Hull` + 简单 `Deck` |
| 4 | 其他零件制作与复用 | 新零件或从部件库复用的零件 | 大型复杂零件可以继续递归拆分 |
| 5 | Blender 组装 | 同一坐标与尺度下的完整船只 | 统一 Pivot、连接、材质、拓扑、碰撞和 LOD |
| 6 | UE5 游戏资产 | 可导入、可运行、保留必要逻辑模块的资产 | Socket、碰撞、LOD、材质和交互接口按单船合同执行 |

每一阶段必须经用户确认后才能成为下一阶段的正式输入。候选稿保持 `DRAFT` 或 `REVIEW`。

## 3. 风格图与零件图的权威边界

- 完整效果概念图负责**风格与整体身份**，不直接承担所有零件隐藏面的精确建模信息。
- 部件设计图只约束其对应零件；不得用某个小部件图反向改变整船用途、尺寸或船型身份。
- 只有当前正在制作的零件需要生成必要视图；不再为整船强制制作固定五视图。
- 某零件需要 AI 3D 多图输入时，视图数量和组合按该零件形状及当前工具能力决定；一致性高于数量。
- Blender 组装文件是零件尺度、相对位置和最终连接关系的权威。

## 4. 船身验证规则

当前首个验证对象是船身，不是整船，也不是小装饰件。

### 4.1 Hull

船身生成范围默认包括外船壳、龙骨、艏柱、艉柱、船腹、首尾过渡、舷弧和连续舷墙。除非单船另行规定，首轮船身不得包含：

- 炮窗及炮窗开口；
- 甲板、艉楼、货舱口、楼梯；
- 桅杆、帆桁、船帆、索具、艏斜桅；
- 舵、锚、灯、绞盘、装饰和松散道具。

### 4.2 Deck

Deck 是独立的简单板件，只需能够在 Blender 中手动缩放并放入船身。首轮不要求复杂贴合、开孔、舱口或细节几何。

### 4.3 验收

船身必须具备可识别且符合设计的侧面轮廓、顶视收窄、首尾体量和船腹；左右不得明显扭曲。导入 Blender 后必须可编辑，并能安装独立甲板。若隔离船身仍无法得到可用结果，应停止继续优化整船图片，改用 Blender 建立核心船体。

## 5. 炮窗是独立逻辑部件

炮窗不得预先做在 Hull 上。需要炮窗的船只在后续阶段使用独立模块，至少预留：

- 可见炮窗框/盖板；
- 用于 Blender 布尔切割船舷的 Cutter；
- 用于绑定火炮及确定朝向的 Cannon Socket/Anchor。

炮窗数量、位置和武装配置由单船设计决定，但不得把炮窗永久焊死在可复用船身生成阶段。

## 6. 复用优先

制作其他零件前必须先检查部件库。可复用零件只调整尺寸、材质、Pivot 和接口，不重复生成。复杂部件可以继续拆分；拆分边界应优先选择自然装配边界，而不是任意切碎网格。

### 6.1 船帆与骨架：先复用，后新建

1. 制作任何新船帆之前，必须先读取[船帆模板目录](sails/README.md)，检查已有帆面、骨架、权重和收放动画的版本与适用范围；不得默认从零建模或重新创建骨架。
2. 模板以“帆型＋收放方式”为基本单位。外形相同但固定点、牵引方向或收拢方式不同，不视为自动兼容；例如沿斜桁收拢和绕前缘卷起的三角帆应分别判断。
3. 采用顺序为：**直接复用 → 对已有模板作尺寸／比例适配 → 确认无法适配后才新建船帆及所需骨架**。帆面需改动不等于骨架必须重做；可继续沿用原骨架的，只制作帆面变体。
4. 同帆型等比例尺寸优先整套缩放。宽高比例不同，先尝试参数化调整帆面、骨骼位置、权重与位移动画，保留兼容的骨骼命名、层级和接口；不得保证所有比例共用不变的动画数据。
5. 适配必须检查满帆、收帆及过渡过程，确认安装点、轮廓、折叠和与桅杆／索具的间距合适，并符合目标船的性能需求。仅尺寸不同、材质不同或换了一艘船，不构成新建骨架的充分理由。
6. 开工前记录：检查过的模板及版本、直接复用／适配／新建的结论。新建时必须说明现有方案不兼容的具体原因，不能以“没有看过旧资产”代替判断；资源不可访问时明确标记待核对，不得声称没有可复用资产。
7. 新模板或比例变体制作后登记到目录，记录帆型、收放方式、源文件、骨架／动画版本、适用比例、三角面数、骨骼数量及验证状态，以供后续船只优先复用。候选与正式模板分开，不把流程验证稿直接作为性能定稿。
8. 资源复用不等于运行时只计算一套骨骼。面向大量船只同屏，仍需按实例、距离和 LOD 评估骨骼变形、组件和渲染成本；本规则不锁定尚未实测的面数或骨骼预算。

## 7. 完整效果概念图规则

1. 默认只输出一张纯画面，不加标题、参数、标签或说明框。
2. 完整容纳船体和最高桅杆，不裁切桅顶。
3. 只负责定调整体风格；不自动扩展成整船多视图板。
4. 必须执行当前绑定材质卡；不得自行做旧、加锈、加污渍或增加未批准颜色。
5. 用户批准前不得登记为正式风格母版。

## 8. 直接修改与重新制作

- 直接修改指定图片/零件时，只改用户明确指出的范围。
- “重新制作目标 T”时，排除 T 自身旧版本，但继续读取当前流程规定的合法上游。
- 对零件而言，合法上游通常是：整体设定、已批准完整效果概念图、部件拆解记录、该零件当前设计合同和材质卡。
- 旧整船线稿、多视图、白模审核图及其提示词不再是任何新阶段的合法上游。

## 9. 材质与工具

1. `MAT-*` 是颜色、粗糙度和表面状态的硬约束，不得修改结构。
2. 当前 AI 3D 主工具为 Tripo 3D；其输出是中间毛坯，必须进入 Blender 清理、定标和组装。
3. 工具指南只能解释执行方式，不得恢复已经删除的整船多视图流程。
4. 本规则写入 Git 后跨会话生效；聊天记忆和旧文件不得覆盖它。
