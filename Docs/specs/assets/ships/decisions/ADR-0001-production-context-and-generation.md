# 船只资产制作：上下文隔离与出图触发规则

## 背景

此前工具存在以下风险：

- 一看到最终目标是图片就过早触发图像生成；
- 在用户要求“重新/重出”时仍读取上一版概念图或视觉母版；
- 把历史聊天、旧提示词或助手自己生成过的描述继续当成设计依据；
- 把材质卡当作风格参考而不是硬约束，从而自行补颜色或表面效果；
- 把单张 `[概念图]` 自动扩展成多视图 concept sheet。

这些行为会削弱 Git 规则、设计档案与材质卡的控制力，并使规则修改无法稳定传递到后续会话和工具。

## 用户决定

用户明确要求将本会话中的制作规则写入持久规则，并至少对所有船只资产制作生效：

1. 游戏开发内容先读取规则，规则读取为第一优先；
2. 先分析文字，再判断是否需要出图；多数交流不需要生成图片；
3. 直接改图时就在指定图片上修改；
4. “重新/重出”表示推翻上一版，不读取规则之外的上下文，尤其不参考上一版概念图/视觉母图；
5. 材质卡是硬约束，材质卡没有的颜色不得自行加入；
6. 材质卡规定的颜色必须严格遵守；
7. `[概念图]` 只负责定调，默认不制作多视图；
8. 已删除/替换的规则不能从旧聊天、旧提示词或模型记忆中复活；
9. 这些规则必须写入 Git，使聊天是否存在都不影响后续执行。

## 决策

创建 `Docs/specs/assets/ships/production-rules.md` 作为 `LOCKED` 的船只资产全局制作规则，并要求：

- `spec-manifest.yaml` 和船只资产索引显式引用；
- 工具上下文协议在单船设计档案之前读取；
- ChatGPT、Google AI Studio、Cursor 等适配层只引用该规则，不维护冲突的第二套事实；
- 旧的“所有出图都必须使用视觉母版作为唯一编辑母版”规则被细分：只在直接改图或用户明确要求参考母版时成立；在 clean-slate 的“重新/重出”中，旧视觉母版图片被排除出生成输入。

## 与材质卡的关系

本 ADR 只规定“材质卡必须作为硬约束执行”的全局行为，不复制任何具体 MAT 卡色值或表面参数。

`MAT-001` 删除做旧驱动规则的具体决定仍由 `Docs/specs/assets/ships/material-cards/MAT-001/decisions/ADR-0001-remove-weathering.md` 负责。

## 后果

- 后续新会话不能靠聊天记忆继续生产，而必须从 Git 重新读取制作规则；
- “重新”不会再被解释为“基于上一版继续优化”；
- 材质卡外颜色和未授权表面效果不再允许由模型自行补充；
- 文本讨论不会因为最终目标是视觉资产就自动触发出图；
- `[概念图]` 默认保持单张定调图，除非用户明确要求多视图。
