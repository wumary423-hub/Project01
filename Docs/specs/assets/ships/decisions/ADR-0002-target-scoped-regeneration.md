# 船只资产制作：`重新`只重置目标产物，不切断上游依赖

## 背景

`SHIP-ASSET-ADR-0001` 将“重新/重出”描述得过于宽泛，容易被工具错误执行为“只读文字规则，排除所有既有视觉产物”。这会破坏船只资产工作流中的正常依赖关系：后续产物本来就可能必须以前一阶段已批准产物作为来源。

## 用户澄清

用户明确规定：

> `重新`做某个内容时，不参考**正在被重新做的那个内容本身的旧版本**；应当回到该内容在当前工作流中规定的来源，依据这些上游来源重新制作。

因此，`重新`不是“清空所有既有上下文”，而是“**目标产物级重置（target-scoped reset）**”。

## 决策

1. 每次出现“重新 / 重出 / 从头做 / 推翻上一版”等指令，必须先识别本次被重新制作的目标产物 `T`。
2. 禁止把 `T` 的旧版本作为本次制作依据，包括旧 `T` 图片、旧 `T` brief、旧 `T` 提示词、旧 `T` 的临时视觉总结，以及被否决的 `T`。
3. 必须继续读取当前权威工作流/设计档案规定的 `T` 的合法上游来源。上游来源可以是文字规范，也可以是已经批准的图片或其他阶段产物。
4. `重新`不得切断生产依赖链，也不得把“历史产物”一概视为禁止输入。判断标准是：该产物是不是当前目标 `T` 的旧版本，还是 `T` 的正式上游来源。
5. 若用户明确要求“基于上一版 T 修改 / 参考旧 T / 在旧 T 上改”，则该任务不按 target-scoped regeneration 执行，而按直接编辑/显式参考执行。
6. 历史聊天、模型记忆、助手旧提示词等只有在已经正式写入当前权威规则/档案后，才能作为上游事实来源；否则仍不得使用。

## 例子

- `重新做[概念图]`：目标 `T = 概念图`。不参考旧概念图/旧 Concept Master 图片；依据当前规则、设计档案、材质卡及该阶段规定的其他上游来源重新制作。
- `重新做[线稿多视图]`：目标 `T = 线稿多视图`。不参考旧线稿多视图；若当前工作流规定它来源于已批准的 `[线稿透视图]`，则必须继续参考该线稿透视图。
- `重新做[概念多视图]`：不参考旧概念多视图；若工作流规定来源为 `[概念图] + [线稿多视图]`，则这两个当前批准的上游产物仍必须读取。
- `重新做[最终多视图]`：不参考旧最终多视图；若工作流规定由 `[概念多视图] + [线稿多视图]` 共同决定，则必须读取这两个上游来源。

## 后果

- “重新”只清除目标产物自身的继承，不清除生产链上游。
- 工具在出图前必须明确：本次目标产物是什么、它的合法上游来源是什么、哪些旧文件因为与目标同类而被排除。
- 任何把“重新”简单执行成“禁止读取所有视觉母版/既有图片”的规则均被本 ADR 替代。
